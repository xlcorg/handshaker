# gRPC Core

OS-независимое ядро Handshaker: контракт метода (reflection), вызов (invoke),
библиотека коллекций, окружения, auth и резолв `{{var}}`-шаблонов. Ядро не знает
про Tauri/specta и про UI.

## Language

### Резолв запроса

**Резолв-пайплайн (resolve pipeline)**:
Единственное преобразование «сохранённый запрос или черновик + коллекция +
активное окружение → effective request». Живёт в ядре; никакая другая поверхность
не повторяет его шаги.
_Avoid_: «фронтовый резолв», sendStep-резолв (исторический TS-двойник, удалён)

**Effective request**:
Полностью разрешённый, готовый к отправке запрос: target (адрес+TLS), тело,
metadata, материализованный auth-заголовок. Результат резолв-пайплайна.
_Avoid_: resolved request, InvokeRequest (историческая проводная форма, удалена)

**Resolve failure**:
Типизированный отказ резолва: полный (дедуплицированный, в порядке встречи)
список неразрешённых переменных плюс цепочка цикла, если он есть. Не «первая
ошибка», а весь диагноз разом.
_Avoid_: UnresolvedVariable (одиночная ошибка старого строгого резолва)

**Dynamic var (билтин)**:
`{{$guid}}`-подобная переменная, генерируемая в момент Send (per-occurrence).
Резолв-пайплайн её не считает неразрешённой — она остаётся литералом до фазы
экспансии билтинов. Пользовательская переменная того же имени побеждает.
Экспансия применяется только к пользовательским шаблонным полям (body, значения
metadata); материализованный auth-заголовок — факт, не шаблон, и не экспандится.
_Avoid_: unresolved var (это другой bucket)

### Коллекции

**Collection link (ссылка коллекции)**:
Именованный внешний URL, принадлежащий коллекции, — быстрый переход к
инструментам сервиса, который коллекция представляет (Grafana, логи, дока).
URL — `{{var}}`-шаблон, резолвится против активного окружения; с неразрешёнными
переменными переход заблокирован (ссылка помечена, показан отсутствующий ключ).
Открывается **эффективный URL**: результат резолва, при отсутствии префикса
`scheme://` дополненный схемой `https://`; хранится ввод как есть. Ссылка с
пустым URL не показывается как переход (видна только в редактировании, помечена).
Порядок ссылок — пользовательский (задаётся при редактировании), не порядок
создания. Носитель — только коллекция; папки и запросы ссылок не имеют.
_Avoid_: service explorer (рабочее название фичи, не термин модели);
service link (носитель — Collection, а не gRPC-сервис из reflection)

### Auth

**Auth pick (выбор auth)**:
Чистый синхронный выбор выигрывающего auth-конфига: ближайший активный
не-`None` по цепочке request → collection, с env-гейтом (конфиг, чей список
окружений не содержит активное, пропускается как отсутствующий). Правило живёт
в ядре ровно один раз; UI спрашивает его через IPC, а не повторяет.
_Avoid_: pickEffectiveAuth (удалённое TS-зеркало)

**Auth materialization (материализация auth)**:
Превращение выбранного конфига в конкретный заголовок: EnvVar — чтение OS-энва;
OAuth2 — `{{var}}`-резолв полей конфига и получение токена через token source.
Асинхронна (в отличие от pick).
_Avoid_: resolve_auth (старое одношаговое имя, объединявшее pick и materialize)

**Token source**:
Шов получения OAuth2-токена по уже разрешённому конфигу. Два адаптера: боевой
провайдер с токен-кэшем и тестовый фейк (oauth-сценарии резолва тестируются без
сети).
_Avoid_: token provider (имя конкретного боевого адаптера, не шва)

### Отправка

**Send (спайн отправки)**:
Единственная точка «запрос/черновик + коллекция + окружение → выполненный вызов +
send report»: резолв-пайплайн → экспансия билтинов → инъекция материализованного
auth-заголовка → активация через contract cache → invoke. На UNAUTHENTICATED с
OAuth2 Send удаляет токен из кэша, получает новый и повторяет unary-вызов один раз
с тем же телом и остальными метаданными. Если повторный вызов тоже вернул
UNAUTHENTICATED, Send снова инвалидирует токен и возвращает этот статус. Отмена и
таймаут — не часть Send, а забота вызывающего слоя.
_Avoid_: оркестрация в IPC-команде (командный слой — адаптер над Send, не дом спайна)

### Вызов

**Call options**:
Пер-вызовные опции invoke (timeout, лимит размера сообщения, …), путешествующие
от UI до транспорта одним растущим значением, а не позиционными параметрами.
Ключ отмены (request id) — не call option: у него свой жизненный цикл.
_Avoid_: перечисление опций россыпью в сигнатурах

**Method kind (вид метода)**:
Четырёхзначная классификация метода по флагам дескриптора `client_streaming` /
`server_streaming`: `unary` / `server` / `client` / `bidi` (= Unary / Server streaming /
Client streaming / Bidirectional streaming RPC у grpc.io). Источник истины — загруженный
контракт. Выполненный вызов запоминает вид, с которым он прошёл; на сохранённом запросе вид
не хранится. Core отказывает вызову, чей путь (unary / stream с выбранным видом) не совпадает
с видом метода, до того как что-либо уйдёт на провод.
_Avoid_: method type / RPC type / call type / тип метода (путается с типами сообщений),
streaming flag, stream kind (не покрывает unary)

**Stream call (стриминговый вызов)**:
Один вызов стримингового метода (server / client / bidi) от Send до stream end.
Отличается от unary тем, что inbound messages приходят по одному и вызов живёт,
пока сервер не завершит его или пользователь не отменит.
_Avoid_: «стрим-запрос», streaming request (запрос — это то, что отправили; вызов — вся сессия)

**Inbound message / Outbound message**:
Одно proto-сообщение, полученное от сервера / отправленное серверу в рамках
stream call. Термин совпадает с proto (`stream <Message>`) и с Contract-табом.
_Avoid_: frame (HTTP/2-термин: один message может занимать несколько кадров), chunk

**Open (открытие)**:
Клиентское действие, начинающее stream call: resolve → auth → activate, initial metadata
ушли на провод, ни одного outbound message. У client-streaming и bidi это отдельный шаг,
за которым следуют отправки сообщений и half-close; у unary и server-streaming Send =
Open + единственный outbound message + half-close одним шагом.
_Avoid_: Invoke (Postman-термин), «подключиться» (activate — только часть Open)

**Half-close**:
Момент, когда клиент закончил отправку outbound messages; сервер может продолжать
отвечать. У unary и server-streaming наступает сразу после единственного outbound message.
_Avoid_: «закрыть стрим» (это отмена, а не half-close)

**Stream end**:
Завершение stream call сервером: финальный gRPC status + trailing metadata. До него
у вызова есть только initial metadata (headers) и накопленные inbound messages.
_Avoid_: «последний фрейм», EOF

**Cancel (отмена)**:
Клиент прерывает stream call до stream end. Полученные inbound messages сохраняются;
серверного статуса нет — это клиентское терминальное состояние, а не stream end.
_Avoid_: «закрыть стрим», «CANCELLED-статус» (это gRPC-код от сервера, при отмене его нет)

**Stream start**:
Момент, когда сервер принял stream call: initial metadata (headers) получены. Граница
дедлайна и первое событие вызова. У client-streaming и bidi наступает поздно — после
half-close или вместе с первым inbound message — и не гейтит отправку outbound messages.
_Avoid_: «подключились» (это activate), «первое сообщение» (headers приходят раньше него)

**Stream store**:
Владелец всех сообщений одного stream call (inbound и outbound) в сыром закодированном
виде на стороне core; живёт, пока на вызов ссылается хотя бы один шаг — черновик или
снапшот истории. Единственный источник для раскрытия тела сообщения, сборки файла и
истории; UI держит только мета и превью.
_Avoid_: buffer, cache (не выселяется и не лимитируется), «лог сообщений»

**Assemble (сборка файла)**:
Конкатенация значения одного bytes-поля всех inbound messages одного stream call в
порядке получения. Источник — Stream store; доступна только в терминальном состоянии
(stream end или cancel). Сообщения без этого поля пропускаются.
_Avoid_: download (файл не скачивается — он уже получен), export (это Save messages),
«склеить чанки»
